# TIR Troubleshooting

Use this section for TIR errors, public-safe UI messages, limitations, and support-required guidance.

Troubleshooting must stay public-safe and must not expose internal runbooks, private source references, or private remediation procedures.

## Planned troubleshooting areas

<div class="product-status-grid">
  <div><strong>Notebook launch errors</strong><span>Messages and user actions for notebook startup failures.</span></div>
  <div><strong>Dataset issues</strong><span>Public-safe guidance for dataset workflow failures.</span></div>
  <div><strong>Training failures</strong><span>Error-message-first help after source-backed extraction.</span></div>
  <div><strong>Inference deployment issues</strong><span>Support boundaries and safe recovery steps.</span></div>
  <div><strong>GenAI API errors</strong><span>Public API errors linked to generated references.</span></div>
  <div><strong>Billing readiness</strong><span>Shared account and billing checks before TIR actions.</span></div>
</div>

## Required pattern

Each troubleshooting page should include:

- Error message.
- What it means.
- Likely cause.
- What to do.
- What not to do.
- Support required: Yes, No, or Sometimes.
- Related docs and API docs.
